# Interactive Whiteboard API & WebSocket Server

Серверная часть приложения для совместной работы над интерактивными досками (Whiteboard).
Стек: **Node.js + Express + Socket.io + SQLite**.

## 📋 Описание функционала

* **REST API** для регистрации, авторизации, управления досками, лайками и шерингом.
* **WebSocket (Socket.io)** для синхронизации холста в реальном времени.
* **Валидация:** Проверка границ холста (1600x900) на сервере.
* **Фокус:** Система блокировки объектов (Locking), предотвращающая одновременное редактирование одного элемента разными пользователями.

---

## 🔑 Обязательные HTTP Заголовки (Headers)

В этом API используются строгие правила валидации заголовков.
**Любой HTTP запрос** должен содержать как минимум первые два заголовка.

| Заголовок | Значение | Где обязателен? | Описание |
| :--- | :--- | :--- | :--- |
| **Content-Type** | `application/json` | **Все запросы** | Указывает формат данных. |
| **ClientId** | `<Ваш_Логин>` | **Все запросы** | Ваш идентификатор (по ТЗ). Например: `IvanDev`. |
| **Authorization** | `Bearer <Token>` | **Приватные запросы** | Токен, полученный при логине. Нужен для действий внутри личного кабинета. |

> ⚠️ **Важно:** Если вы не передадите заголовок `ClientId`, сервер вернет ошибку `400 Missing ClientId header`.

### 👤 1. Аутентификация

#### Регистрация
* **Метод:** `POST`
* **URL:** `/api/auth/register`
* **Headers:**
    * `Content-Type: application/json`
    * `ClientId: <Ваш_Логин>`
* **Body:**
    ```json
    {
      "email": "user@example.com",
      "name": "Alex",
      "password": "Password123!"
    }
    ```

#### Вход (Логин)
* **Метод:** `POST`
* **URL:** `/api/auth/login`
* **Headers:**
    * `Content-Type: application/json`
    * `ClientId: <Ваш_Логин>`
* **Body:**
    ```json
    {
      "email": "user@example.com",
      "password": "Password123!"
    }
    ```
* **Ответ:** `{ "token": "...", "user": {...} }`. Сохраните `token` для следующих запросов.

## ⚡ WebSocket API (Real-time)

Взаимодействие в реальном времени происходит через протокол **Socket.io**.
URL: `ws://localhost:3000`

### 1. Подключение (Handshake)
При инициализации соединения передайте токен авторизации в объекте `auth`.
Если пользователь — гость (на публичной доске), токен передавать не нужно (сервер выдаст имя "Guest").

```javascript
import { io } from "socket.io-client";

const socket = io("http://localhost:3000", {
  auth: {
    token: "ВАШ_JWT_ТОКЕН" // Без слова Bearer
  },
  extraHeaders: {
    "ClientId": "Ваш_Логин"
  }
});

```

### 2. Логика работы с холстом (Flow)

Работа строится на системе **«Фокусов» (Locks)**, чтобы избежать конфликтов редактирования.

1. **Вход:** Вы заходите на доску -> отправляете `JOIN_BOARD`.
2. **Захват:** Вы хотите редактировать объект (mousedown) -> отправляете `REQUEST_FOCUS`.
* Сервер проверяет, свободен ли объект. Если да — блокирует его за вами.
* Другие пользователи получают `FOCUS_TAKEN` (видят рамку и имя, редактировать не могут).


3. **Изменение:** Вы двигаете объект локально (на сервер координаты слать в этот момент не нужно).
4. **Сохранение:** Вы отпускаете объект (mouseup) -> отправляете `RELEASE_FOCUS` с новыми координатами.
* Другие пользователи получают `ELEMENT_UPDATED` и видят объект на новом месте.



---

### 3. Структура объекта (Element Model)

Все объекты на доске имеют следующую структуру. Координаты должны быть внутри холста **1600 x 900**.

```json
{
  "id": "uuid-v4",
  "type": "rect",             // 'rect', 'circle', 'text', 'image', 'line'
  "x": 150,                   // 0 - 1600
  "y": 300,                   // 0 - 900
  "width": 200,
  "height": 100,
  "rotation": 0,
  "content": "Текст или URL"  // Текст или Base64/URL картинки
}

```

---

### 4. События от Клиента (Client -> Server)

| Событие | Payload (Данные) | Описание |
| --- | --- | --- |
| **`JOIN_BOARD`** | `{ "board_id": 10 }` | **Обязательно.** Вход в комнату доски. |
| **`ADD_ELEMENT`** | `{ "board_id": 10, "element": { ... } }` | Создание нового объекта. |
| **`REQUEST_FOCUS`** | `{ "board_id": 10, "element_id": "xyz" }` | Попытка захватить объект для редактирования. |
| **`RELEASE_FOCUS`** | `{ "board_id": 10, "element_id": "xyz", "element_data": {...} }` | Снять фокус и сохранить изменения в БД. |

**Пример отправки сохранения:**

```javascript
socket.emit("RELEASE_FOCUS", {
  board_id: 10,
  element_id: "obj-1",
  element_data: {
     id: "obj-1", x: 500, y: 500, width: 100, height: 100, rotation: 0, type: 'rect'
  }
});

```

---

### 5. События от Сервера (Server -> Client)

| Событие | Payload | Описание действия фронтенда |
| --- | --- | --- |
| **`CURRENT_FOCUSES`** | `{ "el_id": { "userName": "Ivan" } }` | Приходит при входе. Показать рамки блокировки на занятых объектах. |
| **`FOCUS_TAKEN`** | `{ "element_id": "xyz", "user_name": "Alex" }` | Кто-то занял объект. **Заблокировать** его у себя, показать имя. |
| **`FOCUS_RELEASED`** | `{ "element_id": "xyz" }` | Объект освободился. **Снять** блокировку. |
| **`ELEMENT_UPDATED`** | `{ "element_id": "xyz", "element_data": {...} }` | Объект изменен. Обновить координаты/размер на холсте. |
| **`ELEMENT_CREATED`** | `{ "element": {...} }` | Создан новый объект. Добавить его на холст. |
| **`ERROR`** | `{ "message": "..." }` | Ошибка (например, выход за границы 1600x900). Откатить изменения. |

## ✅ Чек-лист проверки работы

1. [ ] При перетаскивании объекта **вы** видите движение плавно.
2. [ ] Другой пользователь видит, что объект **заблокирован** и подписан вашим именем (он не видит движения в реальном времени).
3. [ ] Когда вы отпускаете мышь, объект у другого пользователя «прыгает» в новую точку.
4. [ ] Невозможно перетащить объект за пределы 1600x900 (сервер вернет ошибку `ERROR`).
